## 5. umami 빌드가 "로그를 보세요" 로만 멈춘 것 (09-29)

- 증상: pnpm 버전 맞추기까지는 됐는데 `corepack pnpm@12.3.4 run build` 가 실패 — umami 는 빌드 첫 단계(`check:env`)에서 `DATABASE_URL` 을 요구한다.
- 원인: QA 가 비어 있는 `DATABASE_URL` 을 채우는 것은 **파이썬 서버(임시 sqlite)뿐**이고, 로컬 DB 켜기는 `.env` 가 localhost 를 가리킬 때만 돈다. umami 는 `.env` 자체가 없어 둘 다 해당 없음 → 원인을 말하지 못했다.
- 고침: 켜기 실패 로그에서 빠진 환경변수(umami check-env·Prisma·"Missing env" 문구)를 읽어 **이름을 짚고**, DB 변수면 "DB 를 띄우고 .env 에 주소를 적는다 · 레포의 docker-compose.yml 참고" 를 붙인다 (`common/serve.js` `failHint`). Postgres(DB)를 QA 가 새로 만들지는 않는다는 원칙은 그대로.
- 테스트 57개 통과. umami 를 실제로 돌리려면 사용자가 DB 컨테이너와 `.env` 를 한 번 만든다.

## 6. DB 를 사용자가 직접 만들어야 했던 것 → QA 가 검사용 DB 를 띄운다 (09-29)

- 5절의 안내만으로는 "딸깍 한 번" 이 깨진다 (사용자 지적). PHP 스택은 이미 메모리 DB 를 띄우고 끄면 지우는데, Node 앱에만 빠져 있었다.
- 고침 1 — `common/deps.js` `throwawayDb`: 코드(또는 Prisma)가 `DATABASE_URL` 을 읽는데 환경변수·레포 `.env` 어디에도 없으면,
  DB 종류를 Prisma provider → compose 이미지 → 의존성(pg·mysql2) 순으로 읽어 `qa-db-<프로젝트>` 컨테이너를 **tmpfs(메모리)** 로 띄우고 빈 포트를 서버 환경변수로만 넘긴다.
  레포 `.env` 는 건드리지 않는다. 서버를 끄거나 켜기가 실패하면 컨테이너째 지우고, 지난번에 남은 같은 이름은 켤 때 먼저 지운다. 종류를 모르면(몽고 등) 하지 않는다.
- 고침 2 — `withPm`: 레포 스크립트가 **안에서 다시 부르는** `pnpm` 이 이 맥의 pnpm 11 을 잡아 `engines` 에 걸렸다 (umami `build:packages`).
  `.qa-data/pm-shims/` 에 그 버전을 부르는 작은 실행 파일을 만들어 PATH 앞에 둔다.
- 확인: `node run.js umami --only=N` — 검사용 Postgres 가 뜨고, 마이그레이션·빌드를 지나 서버가 켜져 N 영역 23개 통과. 끝난 뒤 `qa-db-umami` 컨테이너가 사라진 것까지 확인. 테스트 58개 통과.
- 남은 것: umami 로그인 실패 — 기본 관리자 계정(admin/umami)을 QA 가 모른다. ⚙ 설정에 넣으면 된다.

- 확인: outline 에서 검사용 DB 가 1.3초에 준비되고, 그동안 화면 서버가 계속 응답. 테스트 63개 통과.
- 알게 된 것: 옛 QA 화면이 떠 있는 채로 다른 곳에서 같은 프로젝트를 켜면 같은 이름(`qa-db-<프로젝트>`)의 컨테이너를 서로 지운다 — 새 코드를 받으면 QA 창을 닫고 다시 연다.
- **남은 것:** QA 는 outline 을 **React 화면으로만** 알아본다. outline 서버는 **Koa** 인데 QA 에 Koa 어댑터가 없고, Redis·여러 필수 환경변수도 필요하다 — 서버 쪽 검사를 하려면 Koa 지원을 새로 만들어야 한다.
