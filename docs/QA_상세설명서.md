# QA 상세 설명서

[README](../README.md) 에서 옮겨 온 사용법·검사 영역·점수·구조의 전체 설명이다 (2026-09-27, 내용은 그대로).

## 실행

**딸깍** — `QA 실행 (Mac).command` / `QA 실행 (Windows).bat` 더블클릭 → 브라우저에 화면이 열린다.
맥에서 `.command` 가 편집기(VS Code 등)로 열리면: 우클릭 → **다음으로 열기 → 터미널**. 또는 터미널에서 QA 폴더로 가서 `npm run ui`.
처음 한 번 "확인되지 않은 개발자" 경고가 뜨면 우클릭 → 열기.

1. **＋ 프로젝트 추가** → 레포 폴더 경로 (스택은 알아서 찾는다)
2. **⚙ 설정** → 로그인이 있는 서비스면 검사용 계정 (가입 경로가 있으면 비워 둬도 두 개를 자동으로 만든다)
3. **검사 수준**(초급·중급·고급·전문가)을 고르고 **전체 검사** → 꺼진 서버는 QA 가 켜고(설치·빌드·실행), 끝나면 화면이 이어받아 [끄기]로 끌 수 있다
4. 영역별 **조회** → O/X 목록 · 왼쪽 위 **OWASP Top 10** 탭

**명령줄**

```bash
node run.js ~/Developer/my-app              # 폴더를 바로
node run.js pyroguard2d                     # projects/ 나 화면에서 추가한 프로젝트 이름
node run.js my-app --only=B,F,I             # 영역 골라서
node run.js my-app --json > result.json     # 기계가 읽을 결과
node run.js my-app --no-serve               # 꺼진 서버를 켜지 않는다 (코드로 잴 수 있는 것만)
node run.js my-app --ci --fail-under=60     # CI: 지난 검사보다 새 문제가 생기거나 점수가 60 아래면 끝 코드 1
node run.js . --staged                      # 커밋 직전: 스테이징된 파일에 비밀(K 영역과 같은 패턴)·.env 가 있으면 끝 코드 1
node run.js my-app --live=https://x.com     # 배포 주소 검사 — GET·HEAD 만, 한 번에 하나씩, 최대 200번 (QA_LIVE_MAX)
node run.js --live=https://x.com            #   레포 없이도 된다 (주소만으로 볼 수 있는 것만). 설정에 liveUrl 이 있으면 --live 만 줘도 된다
                                            #   훅으로 쓰려면 .git/hooks/pre-commit 에 이 한 줄을 넣는다
node run.js my-app --level=초급              # 검사 수준 — 초급·중급·고급(기본)·전문가 (basic·standard·advanced·expert)
```

### 검사 수준 — 초급 · 중급 · 고급 · 전문가(현역)

같은 레포라도 어디까지 보느냐가 다르다. 수준이 오를수록 보는 영역이 늘고, 여는 화면·누르는 버튼이 많아지고, 판정이 엄해진다.

| 수준 | 보는 것 | 영역 | 화면·버튼 한도 | 판정 |
|---|---|---|---|---|
| **초급** | 기본기 — 뜨는가, 터지는가, 비밀이 새는가, 남의 데이터가 보이는가 | 14개 (1·2·3·4·6·G·N·A·E·F·K·B·C·I) | ×0.5 (빠르다) | 보통 |
| **중급** | + 입력 검증·응답 규격·접근성·보안 헤더·로그·개인정보·느린 API·폼 | 30개 | ×0.75 | 보통 |
| **고급** (기본) | 전체 — 동시성·상태 전이·기능 간섭·업무 흐름·장애 대응 + **권한 상승(가입 때 role:'admin')·동시 수정 유실·실제 CSRF 요청·오픈 리다이렉트·Core Web Vitals(CLS·LCP)** | 전부 | ×1 | 보통 |
| **전문가** | 현역 리뷰어가 출시 전에 보는 기준 — 고급 + **세션 고정·로그인 외 API 요청 제한·파일 업로드 종류·크기 제한·HSTS 설정**, 자동 생성 입력 2배 | 전부 | ×2 | **엄함** — △ 확인 필요도 감점, 접근성 '보통' 위반·느린 API(보통 0.5초 넘음·가끔 3초 넘음)도 문제 |

- 처음엔 **초급**으로 크게 터지는 것부터 잡고, 고친 뒤 수준을 올린다. 출시 전에는 **전문가**.
- 전문가 수준의 △ 는 고치거나 [무시] 에 이유를 적어야 점수가 오른다 — "확인했다" 를 기록으로 남기는 셈.
- 점수·지난 검사와 비교는 **같은 수준끼리만** 한다 (초급 80 점과 전문가 60 점은 견줄 수 없다). 리포트에 수준이 남는다.
- 영역을 콕 집어 돌리면(`--only`, 화면의 영역 조회) 수준과 상관없이 돈다.
- 수준 이름(초급·중급…)과 점수 **등급**(초급·중급 상위…)은 다른 것이다 — "전문가 검사에서 등급 중급" 처럼 읽는다.

**CI (GitHub Actions)** — [`docs/ci/qa-github-actions.yml`](ci/qa-github-actions.yml) 을 대상 레포의 `.github/workflows/qa.yml` 로 복사한다.
푸시·PR 마다 QA 를 돌리고, 새 문제·점수 기준으로 실패를 표시하며, Actions 요약에 표(새 문제·먼저 고칠 것·OWASP)를 남기고 결과(JSON·HTML)를 올린다.

꺼진 서버는 QA 가 켠다 — 명령줄은 검사가 끝나면 다시 끈다. 켤 때 코드가 읽는데 비어 있는 흔한 설정은 **검사용 값**을 넣고
무엇을 넣었는지 알린다 (비밀 키 → 무작위, 파이썬 서버의 `DATABASE_URL` → QA 폴더 안 임시 sqlite). 의존성 설치가 실패해도 이미 깔린 것으로 켜 본다.
서버가 기대는 **로컬 DB·Redis**(`.env` 의 `DATABASE_URL` 등이 localhost 를 가리킬 때)가 꺼져 있으면 먼저 켠다 —
Docker 가 꺼져 있으면 켜고(맥은 Docker Desktop), 그 포트를 쓰는 컨테이너(`docker start`)나 docker compose 서비스를 올린다.
컨테이너가 아예 없으면 README 에 적힌 `docker run …` 명령을 찾아 알려 준다 (새 컨테이너를 멋대로 만들지는 않는다). 원격(운영) DB 는 건드리지 않는다.
**검사용 데이터** — 목록 API 가 비어 있으면(3개 미만) 그 자원을 만드는 경로로 그럴듯한 데이터를 몇 개 만들어 목록·상세·수정 화면까지 검사하고, 끝나면 지운다(지우는 경로가 있을 때). 레포의 시드 스크립트는 기존 DB 를 지울 수 있어 돌리지 않는다. 끄려면 `project.js` 에 `seed: false`.
**화면 로그인** — 브라우저 검사는 로그인 화면을 찾아 검사용 계정으로 직접 로그인한 상태로 돈다 (토큰을 브라우저 저장소에 두는 앱도 로그인 뒤 화면까지). 안 되면 API 로그인 쿠키로 대신한다.
그래도 못 켜면 이유(마지막 로그)를 적고, 서버가 필요한 영역은 **'잴 수 없음'** 으로 점수에서 뺀다 — 못 잰 것을 통과로 세지 않는다.

> 검사는 대상 서버에 검사용 데이터(계정·글·센서 등)를 만들고 지운다. **운영 서버에 돌리지 않는다.**

## 왜 '천 개' 인가 — 하나하나 적지 않고 구조로 만든다

손으로 쓴 검사는 쓴 만큼만 잰다. 여기서는 **구조(모양)** 를 코드에서 읽고, 그 구조에 맞는지를 조합으로 만든다.

| 구조 | 어디서 읽나 | 만드는 케이스 | 판정 |
|---|---|---|---|
| **입력 규칙** (칸 × 형식) | zod · Bean Validation · pydantic · Django 폼 · 설정 | 칸마다 경계값·빈 값·빠짐·타입 바꿈·너무 긴 값·형식 위반·주입 문자열 (칸당 10~25개) + 목록 값 **페어와이즈 조합** | 맞는 값은 **저장돼야**(목록으로 확인), 틀린 값은 **4xx 로 거절 + 안 바뀜** |
| 칸 이름만 앎 | `req.body.x` · `await req.json()` | 같은 변형 | **어떤 값에도 5xx 없음** |
| **경로 × 인증** | 모든 경로 | 토큰 없음·엉터리·형식 다름·서명 변조·내용 변조 | 401/403, 진짜 토큰은 통과 |
| 경로 × 주입 | 쿼리·경로 값을 받는 GET | SQL·NoSQL·XSS·경로 조작·SSRF 페이로드 | 5xx·반사·유출 없음 |
| 경로 × 경계값 | 목록 경로 | page·limit·정렬·검색 극단값 | 5xx 없음 |
| 쓰기 경로 × 본문 모양 | 모든 POST/PUT/PATCH | `{}`·`[]`·null·깨진 JSON·깊은 중첩·프로토타입 오염 | 4xx, 내부 정보 안 새어 나감 |
| 계정 흐름 | 가입·로그인·내 정보 경로 | 가입 → 로그인 → 내 정보 → 로그아웃 → 재사용 | 로그아웃한 토큰은 죽어야 |

실측 (2026-09-26, 실제 서버에 돌린 것):

| 프로젝트 | 스택 | 검사 | 그중 자동 생성 |
|---|---|---|---|
| pyroguard2d | Next.js | 1,326 | 760 |
| django-community-crud | Django | 872 | 524 |
| team-lambda | Express + React | 848 | 464 (검증 스키마가 없어 칸 이름 퍼징) |

규칙이 코드에 없으면(손으로 짠 `if` 검증) 틀린 값을 만들 수 없다. 그때는 **△ '손 검증 — 규칙을 설정에 적으면 전부 잰다'** 로
표시하고, `project.js` 의 `entities` 에 규칙을 적으면 등록·수정·조합·본문 모양을 끝까지 잰다 (예: `projects/pyroguard2d`).

## OWASP Top 10 (2021) — 무엇으로 재는가

모든 보안 검사에 OWASP 항목을 붙여 두었다. 화면의 **OWASP Top 10** 탭이 항목별 통과 / 문제 / 확인 필요 / 못 잼을 보여 준다.

| | 항목 | 이 도구가 재는 것 (영역) |
|---|---|---|
| A01 | 접근 통제 실패 | 인증 매트릭스(B) · 관리자 경로를 일반 계정으로(C) · 남의 데이터 id 바꿔 보기 IDOR(C) · 경로 조작(C) · 로그인 없이 개인정보 응답(P) |
| A02 | 암호화 실패 | 박힌 비밀·기본값 비밀(K) · 깃에 올라간 `.env`(K) · 약한 해시·비밀번호 평문(K) · 쿠키 Secure/HttpOnly/SameSite(H) |
| A03 | 주입 | 위험 싱크(eval·innerHTML·`\|safe`·명령 실행)(I) · SQL 이어 붙이기(요청 값 직접이면 X, 코드 조각이면 △)(I) · 실제 페이로드(I) · 저장형 XSS(I) · 입력 퍼징(F) |
| A04 | 안전하지 않은 설계 | 쓰기 경로에 검증이 있는가(F) · 동시 요청 중복 생성(R) · 요청 크기 상한(O) |
| A05 | 보안 설정 오류 | 보안 헤더·CSP(H) · 서버 버전 노출(H) · CORS 아무 출처 허용(H) · DEBUG·기본 설정(H) · 오류에 스택·SQL 노출(E) |
| A06 | 취약하고 오래된 구성요소 | npm audit · pip-audit(V) |
| A07 | 식별·인증 실패 | 로그인 무차별 대입 · **잠금을 X-Forwarded-For 위조로 푸는가** · 로그아웃 토큰 재사용 · 약한 비밀번호 가입(B) |
| A08 | 소프트웨어·데이터 무결성 | 선언 안 된 패키지·잠금 파일(V) · 신뢰 못 할 역직렬화(pickle·yaml.load)(I) |
| A09 | 로깅·모니터링 실패 | 로그인 실패 기록 · 전역 오류 처리기 · 삼킨 오류 · 상태 확인 경로(L) |
| A10 | SSRF | 사용자가 준 URL 을 서버가 부르는 코드(I) · 내부 주소 페이로드(I) |

## 프로젝트 전체 — 딱 실행하면 먼저 보는 11개

| | 영역 | 무엇을 보는가 | 가중치 |
|---|---|---|---|
| 1 | 자체 테스트 | 레포에 들어 있는 테스트를 그대로 돌린다 (`npm test` · `pytest` · `manage.py test` · `gradlew test`). 실패한 테스트 이름, 테스트가 없거나 0개인 것, DB·환경변수 때문에 시작도 못 한 것을 가른다 | 6 |

K(비밀) 영역은 **깃 기록**도 본다 — 최근 400개 커밋에서 지금은 지웠지만 기록에 남은 키·비밀번호, 예전에 커밋된 `.env`. 이미 샌 것이라 새 키로 바꿔야 한다.

**무시 목록** — 오탐이거나 일부러 그렇게 만든 문제는 결과의 X·△ 줄에서 [무시] 를 누르고 이유를 적는다. 대상 레포의 `.qa-ignore.json` 에 쌓여 다음 검사부터 통과로 센다('무시함' 으로 남는다). 깃에 올리면 팀원·CI 도 같은 기준을 쓴다. 왼쪽 '기준 → 무시 목록' 에서 되살린다.

**▲ 지난 검사와 비교** — 전체 검사끼리 비교해 새로 생긴 문제·고쳐진 문제·점수 변화를 보여 준다 (일부 영역만 돌린 검사는 비교 기준에서 뺀다).

**HTML 리포트** — 전체 검사마다 `reports/<프로젝트>/<시각>.html` 이 생긴다. 파일 하나로 열리고(인터넷 불필요) 그대로 팀에 보낼 수 있다. 화면 요약의 [HTML 리포트 열기].

**★ 먼저 고칠 것 Top 10** — 걸린 항목을 영역 가중치 × 종류(실제로 터지는 것·보안이 무겁다) × 건수로 줄 세워, 영역당 2개까지 골고루 보여 준다.
명령줄은 결과 맨 위에, 화면은 전체 검사가 끝나면 바로 요약에 뜬다.

브라우저 검사는 `playwright-core`·`axe-core` 만 쓰고 브라우저를 따로 내려받지 않는다 — 이 컴퓨터의 크롬·엣지(또는 `QA_CHROME` 경로)를 연다.
`QA 실행` 파일이 처음 한 번 `npm install` 로 깐다. 없으면 이 영역만 '잴 수 없음' 이 된다.

## 점수

```
제품 점수 = Σ(영역 가중치 × 영역 합격률) ÷ Σ(가중치) × √스캔률 × 100      ← 대표 점수
운영 성숙도 = 10개 항목 18점 (CI·자동 테스트·감시·백업·문서 …)            ← 따로 본다 (곱하지 않는다)
```

- **스캔률** 은 얼마나 넓게 봤나, **합격률** 은 본 것 중 얼마나 멀쩡한가. 둘 다 내야 말이 된다.
- 다만 스캔률은 영역 **안에서** 센다 — 대부분의 검사가 찾은 것을 다 보므로 거의 늘 95% 근처다. 넓이를 정직하게 보여 주는 숫자는
  점수 옆의 **"37개 영역 중 N개를 잼"** 이다 (서버가 안 뜨거나 로그인하지 못하면 줄어든다). CI 는 이것이 절반 미만이면 실패로 끝난다.
- **제품 점수와 운영 성숙도는 나란히** 보여 준다. 예전엔 곱해서 '최종' 을 냈는데, 프론트가 98점인 앱도 성숙도 때문에 46점 '초급 상위' 로 보여 오해를 샀다.
  "제품이 지금 멀쩡한가" 와 "멀쩡함이 유지되는 장치가 있는가" 는 다른 질문이다. (곱한 값은 리포트 JSON 의 `combined` 에 참고로만 남긴다)
- **△ 확인 필요** 는 기계가 확신할 수 없는 것 — 점수에 넣지 않고 사람이 볼 목록으로 남긴다 (전문가 수준에서는 감점).
- **손댈 곳** — 같은 원인에서 나온 문제를 묶어 센다. 같은 경로에 이상한 입력 20가지가 모두 500 이면 문제 20건이지만 손댈 곳은 1곳.
  '자동으로 만든 시험 입력 N개' 는 검사에 쓴 입력의 수이지 문제 수가 아니다.
- **잴 수 없음(해당 없음)** 영역은 점수에서 뺀다 (서버 꺼짐, 그 기능이 없음).
- **설정 오류는 제품 결함이 아니다** — ⚙ 설정의 계정으로 로그인하지 못하면(비밀번호 틀림·잠김) 결함 목록·먼저 고칠 것에 넣지 않고 '⚠ 설정 오류' 로 따로 알린다.
  가입 경로가 있으면 검사용 계정을 만들어 이어 가고, 그것도 안 되면 로그인이 꼭 필요한 영역은 '설정 오류로 못 잼' 으로 점수에서 뺀다.
- **점수가 바뀐 이유** — 지난 검사와 비교할 때 영역마다 전·후 점수와 이유(이번엔 못 잼 · 검사 수 · 확인 필요 수)를 보여 주고,
  두 번 다 잰 영역끼리만 매긴 점수를 따로 낸다. 코드가 그대로인데 점수가 흔들리면 대개 못 잰 영역이 달라진 것이다 (예: 직전 검사의 무차별 대입 검사로 로그인이 잠김).
- 등급(제품 점수 기준): 90~ 대기업 · 75~ 중급 상위 · 60~ 중급 · 45~ 초급 상위 · 30~ 초급 · ~29 미완성.
  100 은 "버그가 없다" 가 아니라 **"빠뜨릴 구조가 아니다"** 이다.

## 프로젝트 전용 설정 — `projects/<이름>/project.js` (선택)

코드에서 추정할 수 없는 것만 적는다. 화면에서 추가한 프로젝트는 이 파일 없이
`.qa-local.json`(이 컴퓨터에만, 깃 제외)에 레포 위치·계정·포트만 저장된다.

```js
module.exports = {
  name: '보여 줄 이름',
  root: '~/Developer/my-app',                       // 화면 ⚙ 설정이 우선
  auth: { loginPath: '/api/login', fields: { password: 'password' } },   // 로그인 모양이 특이할 때만 (평소엔 코드에서 추정)
  publicRoutes: [{ method: 'GET', path: '/api/notices', why: '메인 화면 공지' }],       // 일부러 열어 둔 경로 — 근거와 함께
  keptRoutes: [{ method: 'POST', path: '/api/sms/send', why: '화면 버튼만 아직 없음' }], // 안 부르지만 남긴 경로
  entities: [/* 손 검증이라 코드에서 규칙을 못 읽는 자원 — projects/pyroguard2d 참고 */],
  serveEnv: { password: 'ADMIN_PASSWORD', random: ['SESSION_SECRET'] },  // 서버 켤 때 넣을 환경변수
};
```

- `projects/<이름>/probes/<칸>/<영역>.js` — 그 프로젝트에만 있는 업무 검사. 같은 영역 글자면 범용 검사 **뒤에 덧붙고**
  (`[전용]` 표시), `override: true` 면 바꾼다. 서버가 꺼졌거나 로그인하지 못하면 건너뛴다.
- 예시: `projects/pyroguard2d` (119 OTP 승인 범위·재실자 정보·EV 화재 흐름·센서 규칙),
  `projects/crossfit-grove` (공개 경로 · 배포 점검 `check-live.js` · 커밋 전 비밀 검사 `check-staged.js`).

## QA 자체 테스트

```bash
npm test             # 단위 + 회귀 (시험용 레포를 켜고 브라우저로 끝까지 검사 — 1~2분)
npm run test:unit    # 단위만 (1초)
```

`tests/fixtures/` 의 레포 두 개에는 버그를 일부러 심었다 — 코드에 박힌 비밀 키, 병합 충돌 표시, 없는 DOM id, 깨진 이미지,
화면에 찍히는 undefined·NaN, 문법 오류, 숫자를 넣으면 500 나는 API, 서버에 없는 API 를 부르는 화면, 실패하면 죽는 화면 등.
회귀 테스트는 QA 가 이걸 **모두** 잡는지 영역별로 확인한다. QA 를 고치다 어떤 검사가 조용히 죽으면 여기서 걸린다.
푸시·PR 마다 GitHub Actions(`.github/workflows/test.yml`)가 돌린다. 새 검사를 만들면 시험용 레포에 버그를 하나 심고 단정을 더한다.

## 로그인 입구가 여러 개인 앱 (관리자 + 회원 + 직원)

⚙ 설정에 넣는 계정은 **주 로그인 입구 하나**의 것이다 (화면에 어느 경로인지 적혀 있다 — 예: 관리자 비밀번호 → POST /api/admin/login).
비교 대상이 환경변수(`ADMIN_PASSWORD` 등)면 레포 `.env` 값을 알아서 쓰므로 비워 둬도 된다.

그 밖의 로그인 입구는 **코드에서 계정 얻는 길을 찾아** 자동으로 들어간다 (`common/roles.js`):

| 찾은 길 | 하는 일 |
|---|---|
| 가입 — 입구 옆에 `/register`·`/signup` | 가입해서 계정 2개 |
| 관리자가 만든다 — 입구가 읽는 테이블에 넣는 관리자 기능 (`INSERT INTO members` 를 하는 `POST /api/members`) | 관리자로 계정 2개를 만들고, **끝나면 지운다**. 비밀번호는 만들 때 넣거나, 코드의 기본 규칙(전화번호 뒷 4자리)을 읽어 맞춘다 |
| 공용 비밀번호 — 계정 없이 환경변수 하나와 비교 | 그 값으로 들어간다 |
| 못 찾음 | ⚙ 설정에 **그 입구의 칸만** 뜬다 |

그 계정으로 C 영역이 두 가지를 더 본다: **회원 A 가 회원 B 의 id 로 부르면 막히나 (IDOR)**, **회원 토큰으로 관리자 가드가 붙은 경로가 막히나**.
쓰기는 방금 만든 검사용 계정에만 한다.

## 배포 주소 검사 — `--live` (읽기 전용)

로컬에서 통과해도 올린 것이 실제로 그런지는 다르다. 운영 서버에 흔적을 남기지 않는 것만 한다 — **GET·HEAD 만** (한 함수에서 강제),
로그인·쓰기·무차별 대입·퍼징 없음, 한 번에 하나씩 쉬면서, 최대 200번. **주소는 막지 않는다** (허락받은 남의 사이트도 돌린다).

| 주소만으로 | 레포를 같이 주면 더 |
|---|---|
| 첫 화면·응답 속도 · http→https · 인증서 남은 날 · HSTS | 코드에 로그인 가드가 있는 GET API 가 배포본에서도 막히나 (옛 코드가 떠 있나) |
| 보안 헤더 (CSP·액자 막기·nosniff·referrer·서버 종류) | 코드에 있는 화면이 배포본에서 열리나 |
| `/.env`·`/.git`·백업 SQL·`actuator` 같은 파일 · 소스맵(.map) | public·static 폴더의 js·css 가 배포본과 같나 |
| 없는 주소의 오류 화면에 스택·경로가 나오나 · CORS 가 아무 Origin 에 쿠키를 허락하나 | 설정의 `removedRoutes` 가 정말 사라졌나 |

결과는 `reports/<프로젝트>/live-<시각>.json`, 문제가 있으면 끝 코드 1.

## 한계 — 미리 밝혀 둔다

- **버튼은 누르지만 저장은 하지 않는다.** 쓰기 요청을 막고 가짜 성공 응답을 주므로, 서버가 실제로 거절했을 때만 나는 화면 오류는 못 잡는다. 위험해 보이는 버튼·폼 제출은 누르지 않는다. 색·디자인의 어색함도 못 본다.
- **부하 시험이 아니다.** 응답 크기·시간만 잰다.
- **규칙은 코드에 적힌 만큼만 읽는다.** 손으로 짠 `if` 검증은 규칙을 몰라 '5xx 가 안 나는가' 만 보고 △ 로 남긴다.
- **위험한 경로는 건드리지 않는다** — 문자·메일 발송, 결제, 탈퇴, 비밀번호 재설정, OTP·인증코드 확인(잠금이 걸리므로).
  로그인 무차별 대입은 맨 마지막에, 가짜 출발지 주소로 잰다.
- **`확인 필요` 는 결론이 아니다.** 사람이 봐야 하는 목록이다.
