# 2026-09-26 스택별 QA 도구로 나누기

## 결론

QA 를 **스택 조합마다 따로 도는 도구**로 나눴다. 도구 안은 **순수 프론트 / API 받아오는 프론트 /
API 기능 / 보안** 네 칸이다. 점수 공식은 `common/` 하나를 같이 써서 도구끼리 숫자를 비교할 수 있다.
지금은 틀만 잡았다. Grove 도구(`express-ejs`)만 채워져 있고, 나머지 여섯 개는 빈 칸이다.

## 방향이 바뀐 과정

처음 계획은 "도구 하나가 모든 스택을 어댑터로 훑는다"였다. 사용자가 이걸 뒤집었다.

> 모든 스택을 다 훑는 게 아니라 스택별로 돌릴 수 있는 도구를 여러 개 만들고 싶다.
> 리액트+장고면 그 도구, 리액트+자바면 그 도구. 폼이 잘 잡히면 세세한 부분도 채워 넣을 거다.
> 순수 프론트, API 받아오는 프론트, API 기능, 보안으로 나눠서 만들 거다.

## 구조

```
common/          core.js · runner.js · grading.js · maturity.js — 모든 도구가 같이 쓴다
_template/       새 도구의 틀 (cp -R _template <이름>)
express-ejs/     CrossFit Grove — 26개 영역 완성
react-express/   Team-Lambda
react-spring/    Team_Namoo (+ classification-api FastAPI)
django-template/ django-community-crud
expo-express/    healthcheck-app-frontend + backend
nextjs/          pyroguard2d
static-js/       universeproject — 서버가 없어 front 네 개와 K 만 남김
```

26개 영역을 네 칸에 나눈 기준:

| 칸 | 영역 |
|---|---|
| 순수 프론트 (`front/`) | G 화면연결, N 탐색, U 문구, Z 빈 상태 |
| API 받아오는 프론트 (`front-api/`) | A API 계약, J 응답 규격, Y 숫자 일관성 |
| API 기능 (`api/`) | D, E, F, L, M, O, Q, R, S, T, W, X |
| 보안 (`security/`) | B 인증, C 권한, H 헤더, I 주입, K 비밀, P 개인정보, V 의존성 |

## 바뀐 코드

- `lib/`, `probes/`, 루트 `run.js` → `common/` 과 `express-ejs/` 네 칸으로 옮김 (git mv, 이력 유지)
- 러너(`common/runner.js`): 도구 폴더를 받아서 돈다. 칸별 점수를 따로 내고,
  `todo: true` 인 영역은 **빈 칸으로 세서 점수에서 뺀다.** 만든 영역이 없으면 0점 대신 "점수 없음".
- 스택마다 다른 것(API 경로 찾기, 로그인)은 도구의 `stack.js` 로 뺐다. Grove 의 관리자 로그인과
  `backend/routes` 긁기가 `core.js`·`run.js` 에서 `express-ejs/stack.js` 로 이동.
- `common/maturity.js` 의 "QA 도구가 붙어 있다" 판정: `QA/run.js` → `QA` 폴더 유무 (루트 run.js 가 없어졌다)
- 돈을 다루는 서비스가 Grove 뿐이라 나머지 도구에서는 `m_money.js` 를 지웠다.

## 확인한 것

- 모든 영역 파일·러너·stack.js 가 로드된다.
- **점수 공식이 옮기기 전과 같다** — 최근 Grove 리포트 5개의 결과를 새 공식에 넣어 기존 점수와 똑같이 나옴.
- 여섯 개 새 도구가 전부 실행되고 "점수 없음 · 빈 칸 N개" 로 끝난다.
- **Grove 실제 실행은 못 했다** — 서버와 DB(도커)가 꺼져 있었다. 다음에 서버를 띄우고
  `QA_ADMIN_PW=… node express-ejs/run.js` 로 이전 점수(64.9)와 같은지 봐야 한다.
