# 2026-09-28 — gstack 검사 기능과 비교: 우리에게 없는 것

gstack(v1.91.2.0, `github.com/garrytan/gstack`)을 받아 **검사하는 스킬 7개**의 원문을 읽고,
항목마다 우리 코드에 같은 검사가 있는지 grep 으로 확인했다.
읽은 것: `qa`(+ `qa-patterns`·`issue-taxonomy`), `cso`(보안 감사 단계·스캐너), `health`, `benchmark`, `canary`, `review/checklist`, `review/design-checklist`.

## 결론

- gstack 의 검사는 **AI 가 매번 판단**한다 (화면을 보고, 코드를 읽고). 우리는 **정해진 코드가 판단**한다 (토큰 0).
  그래서 gstack 항목 중 "AI 눈이 있어야 하는 것"(레이아웃이 어색한가, 문구가 헷갈리는가, 디자인이 AI 티가 나는가)은 옮길 수 없다.
- **코드로 옮길 수 있는데 우리에게 없는 것은 14가지**다. 아래 표 — 우선순위는 "사고가 났을 때 피해 × 만들기 쉬움" 순.
- 이미 있는 것도 많다: 모바일 375px 가로 넘침, 깨진 이미지, 실패한 요청, JS 크기, 콘솔 오류, 링크, 로그아웃 뒤 토큰, 깃 기록 속 비밀, 의존성 취약점, N+1, 경합, 시간대, 결과 비교(회귀).

## 우리에게 없는 것 — 코드로 옮길 수 있는 14가지

## 옮기지 않는 것 (AI 눈이 필요하거나, 우리 방향과 다름)

- 화면이 어색한지·문구가 헷갈리는지·"AI 티 나는 디자인"(보라색 그라데이션, 3칸 기능 소개 등) 판단 — AI 판단이 핵심이다.
- **버그를 찾으면 직접 고쳐서 커밋**(qa Phase 8) — 우리는 "토큰 0 으로 찾기"가 방향. 고치기는 [AI 에게 고쳐 달라기 — 복사] 버튼으로 넘긴다.
- 사용자의 실제 브라우저(로그인된 세션)로 돌리기 — 우리는 계정을 코드에서 찾아 스스로 로그인한다 (오늘 만든 다른 입구 계정 포함).
- 외부 스캐너 6종(Gitleaks·OSV·Semgrep·zizmor·Trivy·Schemathesis)을 컨테이너에서 돌리기 — 무겁다. 2번(zizmor 가 하는 일)과 12번(Trivy 설정 검사)의 핵심만 코드 검사로.

## gstack 에서 배울 만한 운영 방식

- **점수에 "잰 범위"를 같이 적는다** — 안 잰 분류는 빼고 "잠정"이라 쓴다. 우리도 이미 한다 (37개 중 N개 잼).
- **같은 원인은 한 번만 깎는다** — 우리도 오늘 "한 원인 묶기"를 넓혔다.
- **운영 주소에서 쓰기 동작은 한 번 묻고 한다** ("보는 건 허락, 바꾸는 건 따로") — 우리 `--live` 는 아예 읽기만 한다.
