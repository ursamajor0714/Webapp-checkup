# 2026-09-30 — outline 화면 예외의 원인

어제(`2026-09-29_정리_전면점검부터_umami까지.md` 10절) outline 검사에서 "모든 화면이 같은 예외(`b`·`j`)로 멈춘다" 가 남았다. 원인을 실제 크롬으로 확인했다.

## 결론

**outline 은 멈추지 않는다 — QA 의 판정이 틀렸다.** 화면은 정상으로 뜨고, 장애 때도 오류를 알린다.
예외는 outline 이 내부 오류 객체를 **잡지 않고 던진 것**(처리 안 한 Promise 거절)이라 콘솔에만 남는다.

## 확인한 것 (QA 로 outline 을 켜고 크롬으로 첫 화면)

| 경우 | 화면 | 남은 예외 |
|---|---|---|
| 평소 (로그인 안 함) | "워크스페이스 생성" 첫 설치 화면이 정상으로 뜬다 | `auth.info` 가 401 → `AuthorizationError` |
| API 가 전부 500 | "구성을 로드하지 못했습니다 … 서버 로그를 확인하십시오" | `RequestError: Error 500` |
| 네트워크 끊김 | 같은 안내 (몇 번 다시 시도한 뒤에 뜬다) | `NetworkError` |

- 리포트의 `b`·`j`·`S` 는 **압축된 코드의 오류 클래스 이름**이다. 메시지가 비어 있어 이름만 보였다. 진짜 이름은 Playwright 의 `e.name` 에 있다.

## QA 에서 고친 것

| 무엇 | 고침 |
|---|---|
| 예외 글이 `b` 한 글자 | 공용 `errText` (`common/browser.js`) — 메시지가 한 글자면 오류 이름(`AuthorizationError`), 아니면 `이름: 메시지`. 2·5·8·10 영역 모두 |
| 8: 화면이 오류를 알렸는데 남은 예외만 보고 "멈춘다"(X) | 오류를 알렸으면 확인 필요(△) — "오류를 알린다, 다만 잡히지 않은 예외도 남긴다" |
| 8: 네트워크 끊김을 "하얀 빈 화면"(X) | 2.5초에 봐서 — 다시 시도한 뒤에 안내를 띄우는 앱이 있다. 비어 있으면 6초 더 기다려 본다 |
| 2: 로그인 안 한 화면의 `AuthorizationError` 를 문제(X) | 인증 오류 예외는 확인 필요(△) — 로그인하지 않아 앱이 401 을 오류로 던진 것 |

- 결과: 2 영역 문제 23 → 11 (남은 것은 JS 4.3MB 무게 등), 8 영역 문제 15 → 1.
- 남은 진짜 1건: `/desktop-redirect` 는 API 가 실패하면 **안내 없이** 예외로 멈춘다.
- 테스트 67개 통과.
