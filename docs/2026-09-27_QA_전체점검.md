## 결론

구조와 방향은 좋다. 레포 6개(Django·Spring+FastAPI+React·Express·Expo·Express+React·Next)에 돌려도 **실행 오류는 한 번도 없었다.**
하지만 **"검사는 대상에 흔적을 남기지 않는다"** 는 약속이 깨져 있다. 시험 서버에 QA 를 **한 번** 돌리니:

## P0 — 실제 피해가 날 수 있는 것

### 1. 처리 코드가 문자를 보내는 경로를 QA 가 두드린다 [재현]

- 위험 경로 판단(`generate.js` `DANGEROUS`)이 **경로 이름만** 본다 (`sms`·`send`·`mail` …).
- 시험 서버의 `POST /api/applications`(이름엔 위험 단어 없음, 처리 코드가 문자 발송)에 QA 한 번 → **문자 50통.**
- CrossFit 도 같은 꼴이다. 쓰기 경로 69개 중 처리 코드가 문자를 보내는 것은 2개 — `POST /api/sms/send` 는 이름으로 걸러지지만 **`POST /api/applications` 는 걸러지지 않는다** (`routes/applications.js:54` `sendSms`).
  지금은 로컬 `.env` 에 알리고 키가 없어 발송이 안 됐다. **키를 넣는 순간 실제로 나간다** (건당 과금, 실제 번호일 수 있다).
- 고치는 방향: 처리 코드(`r.handler`)에 `sendSms|sendMail|nodemailer|aligo|twilio|solapi|stripe|toss|fetch("https:` 가 있는 쓰기 경로는 기본으로 건너뛰고 "외부로 나가는 경로라 건드리지 않음" 으로 남긴다.
  CrossFit 은 이것만으로 두 경로 모두 잡힌다 (문자 함수를 부르는 파일이 이 둘뿐). 다른 모듈을 거쳐 부르는 경우까지 잡으려면 `require` 를 한 단계 따라간다.

### 2. 검사가 대상 DB 에 데이터를 남긴다 [재현]

- 시험 서버: 한 번에 **141행**이 남았다. CrossFit 로컬 DB 의 `applications` 는 **412행 전부 QA 흔적**이었다 (행 내용 조회는 자동 모드 안전장치가 막아 개수만 확인).
- README 는 "만들고 끝나면 지운다" 지만, 지우는 건 `seed.js` 의 몇 개뿐이고 그마저 지우는 경로가 없으면 남긴다.
- 남기는 곳: F 입력 퍼징 · R 동시 5번 · D 중복 검사 · M 금액 · I 저장형 XSS(`<img onerror>` 가 든 행) · C·W (지우는 경로·id 가 없을 때).
- 고치는 방향: 영역마다 만든 것을 `ctx.created` 에 모아 `finish` 에서 지운다. 지울 수 없으면 리포트에 "남긴 데이터 N개 (경로별)" 를 적는다.
- **CrossFit 의 412행은 손대지 않았다.** 지울지는 직접 정한다.

### 3. 인증 검사가 QA 자신을 로그아웃시키고, 계정을 잠가 뒷정리를 막는다 [재현 — 새로 찾음]

- B 영역의 인증 매트릭스가 모든 경로에 "진짜 토큰" 요청을 보내는데 **로그아웃 경로도 포함**한다 → 시험 서버 기록상 **1번 토큰(owner)이 로그아웃**됐다.
- 이어서 무차별 대입 검사가 계정을 잠근다 (시험 서버는 IP 가 아니라 계정에 잠금).
- 그 결과 `finish` 의 검사용 데이터 정리가 **"3개를 지우지 못했다: 401"** 로 실패했다 — 다시 로그인하려 해도 잠겨 있다.
- 고치는 방향: 인증 매트릭스의 진짜 토큰 요청에서 로그아웃·탈퇴 경로를 뺀다 (`DANGEROUS` 재사용). 뒷정리는 무차별 대입 검사 **앞에서** 하거나, B 는 전용 세션으로 돈다.

### 4. 폴더 경로로 돌리면 프로젝트 설정이 통째로 빠지고, CI 가 거의 안 재고도 통과한다 [재현]

```
node run.js ~/Developer/CROSFIT-GROVE   → id CROSFIT-GROVE · 공개 경로 0개 · 계정 없음
node run.js crossfit-grove              → id crossfit-grove · 공개 경로 13개
```

- `resolveProject` 가 이름이 아니면 새 프로젝트로 만든다 (같은 폴더를 가리키는 설정을 찾지 않는다).
- **CI 템플릿이 이 방식이다.** CI 처럼 서버 없이 폴더 경로로 돌려 보니: **37개 영역 중 23개를 못 쟀는데 "제품 점수 82 · ✓ CI 통과"** (종료 코드 0).
  GitHub 에서는 DB 가 없어 서버가 안 뜨므로 이게 기본 결과다 — CI 가 초록불이어도 대부분을 안 본 것이다.
- 다른 레포 6개도 서버 없이 돌리면 23~26개 영역을 못 재고 63~85점(대부분 "중급 상위")이 나온다.
- 고치는 방향: ① 경로로 받으면 `projectDefs()` 에서 root 가 같은 것을 먼저 찾는다 ② `--ci` 에서는 "잰 영역 비율" 도 기준으로 — 서버가 안 떴으면 실패로 ③ 점수 옆에 "37개 중 14개 영역만 잼" 을 크게.
- **사본에 넣어 시험 [재현]:** ①② 를 넣으니 폴더 경로 실행에 공개 경로 13개가 적용되고, 서버 없는 CI 는 "잰 영역이 14/37 뿐이다 — 점수를 믿을 수 없다" 로 **실패(종료 코드 1)** 한다. `npm test` 19개 통과.

### 5. 로그인이 막히면 결과가 왜곡된다 [재현]

- **코드만 보는 검사까지 사라진다:** `runner.js` `LOGIN_ONLY` 에 Q·D 가 있어, 비밀번호가 틀리면 CrossFit 의 **N+1 문제 4건**(서버 없이도 잡히는 것)이 리포트에서 빠진다.
- **못 잰 것을 "고친 것" 으로 센다:** 코드가 그대로인데 "새 문제 0 · **고친 것 49**" 가 나왔다 (`diffWithPrevious`).
- **잠김을 "비밀번호 확인" 으로 안내한다:** 서버를 켜 둔 채(화면에서 쓰는 방식) 두 번 돌리니, 첫 검사가 잠근 계정 때문에 두 번째 검사가 **올바른 비밀번호인데도** "아이디·비밀번호를 확인한다" 로 나왔다. 잠김 판단이 429 만 보고 423·"잠김" 문구를 모른다.
- **비밀번호가 틀리면 한 번에 실패 2회씩 쌓는다:** API 로그인 1회 + 화면 로그인(`uiLogin`) 1회. 화면에서 서버를 켜 둔 채 세 번 돌리면 잠금(5회)에 걸린다.
- 고치는 방향: 영역 안에서 로그인이 필요한 부분만 건너뛰기 · 두 번 다 잰 영역끼리만 비교 · 423·"잠김|locked" 도 잠김으로 · API 로그인이 실패하면 화면 로그인은 하지 않기.
- **사본에 넣어 시험 [재현]:** 틀린 비밀번호 한 번에 실패 2→**1회** · 잠긴 계정을 "**계정이 잠겨 있다**" 로 안내 · 영역 하나만 못 잰 비교에서 '고친 것' 1→**0** · `npm test` 19개 통과 (`재현도구/고친사본.patch`).

### 6. QA 요청에 제한 시간이 없다 — 한 경로가 붙잡으면 영원히 멈춘다 [재현 + 고침 시험]

- 시험 서버에 응답하지 않는 경로 하나를 두니 **150초가 지나도 끝나지 않았다** (그 경로엔 요청 1개만 갔다).
- QA 사본에 한 줄(`signal: AbortSignal.timeout(15000)`)을 넣으니 **121초에 끝났다.** 다만 같은 경로에 요청 8개가 15초씩 기다렸다 → 한 번 시간 초과가 난 경로는 나머지를 건너뛰어야 한다.
- 같은 함수가 실패하면 한 번 더 보내는데 **POST 도 다시 보낸다**: 저장 직후 연결이 끊기게 하니 **8행 → 12행 (4행 중복)**. R(중복 생성) 판정을 흐린다. 재시도는 GET 만.

## 고치는 방향 시험 (QA 사본에 넣고 같은 시험 서버로) [재현]

P0-1·2·3 의 고치는 방향을 QA **사본**(레포는 그대로)에 넣어 같은 시험을 돌렸다.

| | 지금 QA | 고친 사본 |
|---|---|---|
| 문자 발송 | 50통 | **0통** — 처리 코드에 문자·메일·결제 호출이 있는 경로를 규칙 목록에서 뺐다 (모든 영역이 `ctx.contracts` 를 쓴다) |
| owner 로그아웃 | 됨 | **안 됨** — 인증 매트릭스 "진짜 토큰" 에서 로그아웃 경로를 뺐다 |
| 검사용 데이터 뒷정리 | 401 로 실패 | **3개 지움** |
| 남은 데이터 | 141행 | **61행** — `ctx.call` 을 감싸 POST 2xx + 응답 id 를 모두 기록하고 `finish` 에서 지웠다. items 는 0행까지 지워졌다 |

남은 61행과 시험하며 드러난 것:
- **지우는 경로가 없는 자원**(applications 11행)과 **응답에 id 를 안 주는 자원**(bookings 50행)은 지울 수 없다 → 이제 리포트에 "남긴 것: 경로별 N개" 로 드러난다. 이런 경로는 퍼징 횟수를 줄이거나(한두 건만) 설정에서 끌 수 있어야 한다.
- 인증 매트릭스(E·B)는 `ctx.contracts` 가 아니라 경로 목록을 직접 쓴다 — 외부로 나가는 경로 거르기를 여기에도 걸어야 한다.
- **처리 코드 자르기의 허점:** 문자 경로 거르기가 `DELETE /api/items/:id` 까지 걸렀다. Express 어댑터가 경로 하나의 처리 코드를 "다음 경로 선언 전까지" 로 자르는데, 그 사이에 정의된 `function sendSms` 가 딸려 들어왔다.
  호출(`sendSms(`)만 보고 정의(`function sendSms`)는 빼야 한다. 이 허점은 F 영역의 "손 검증 감지" 등 처리 코드를 읽는 다른 판정에도 똑같이 있다. → 사본에서 호출만 보게 고치니 오탐이 사라지고 문자는 0통 그대로였다 [재현].

## P2 — 정리하면 좋은 것 [코드]

- `common/core.js` 의 `makeCtx`·`sql`(docker psql)·`walk` 는 아무도 쓰지 않는다 (옛 도구 흔적, 약 70줄).
- F 영역의 `finding`(검증 스키마 없음)을 러너가 버린다 — 화면은 보여 주도록 짜여 있는데 값이 안 온다.
- `generate.js` 가 넘기는 `withFormCsrf: true` 를 `request()` 가 읽지 않는다.
- `b_auth.js` 의 `saved = ctx.config.publicRoutes … = saved` 는 아무것도 하지 않는다.
- 8번 영역의 "오류를 알렸다" 판정 단어에 `연결`·`네트워크` 가 있다 — 화면 어디든 이 단어가 있으면 통과.
- 윈도우 실행 파일(`QA 실행 (Windows).bat`)은 `node_modules\axe-core` 가 있으면 설치를 건너뛴다 — QA 에 새 부품이 추가돼도 윈도우에선 깔리지 않는다 (맥 실행 파일은 `package.json` 이 더 새것인지 본다).
- QA 화면 자체에 파비콘이 없다(`/favicon.ico` 404) — QA 가 다른 레포에서 문제로 잡는 항목이다. [재현]
- 지난 리포트가 있어도 화면을 열면 요약이 아니라 "시작하기" 가 뜬다 — 점수 칩을 눌러야 요약이 나온다. [재현] (요약의 QA 버전 경고·HTML 리포트 링크는 맥 크롬에서 제대로 뜨는 것을 확인)
- 영역을 골라 돌린 검사(`--only`)도 리포트 파일을 남긴다 (`finish` 가 `full` 과 상관없이 저장). 화면의 '지난 검사' 는 가장 최근 파일을 읽으므로, 명령줄로 영역 하나만 돌리면 **화면 요약이 영역 1개짜리 리포트로 바뀐다.** [재현: 파일 생성 확인]
- 파이썬 설치 기록(`installed`)이 한 번 성공하면 requirements 가 바뀌어도 다시 설치하지 않는다.
- `runner.js:93` 주석 위치, `project.js:99-100` 중복 주석.
- `projects/crossfit-grove/check-staged.js`(커밋 직전 비밀 검사)는 K 영역과 비밀 패턴을 따로 갖고 있다 — 범용 `node run.js <레포> --staged` 로 옮기면 어느 레포든 커밋 전 훅으로 쓸 수 있고 패턴도 한 벌이 된다.
- **배포 주소 모드의 씨앗이 이미 있다** — `projects/crossfit-grove/check-live.js` 가 운영 사이트(cfgrove.com)를 읽기 전용으로 점검한다. 범용으로 옮기면 우선순위 문서의 "배포 주소 모드" 절반이 끝난다.

## QA 를 QA 자신에게 돌려 본 결과 [재현]

- QA 는 자기 자신을 **정적 사이트 하나(`common/ui`)** 로만 알아본다 — `ui.js`·`run.js` 같은 프레임워크 없는 Node 서버·CLI 는 감지하지 못한다.
- 그래서 37개 영역 중 **29개를 못 재고 "제품 점수 98.7 · 대기업 수준"** 이 나온다. P0-4 의 "잰 영역이 적어도 점수는 높다" 가 가장 극단적으로 드러난 예.
- 걸린 3건은 모두 **오탐**이었다:
  - 병합 충돌 표시 — `tests/fixtures/buggy-static/notes.md` (일부러 심은 시험용). 6번 영역은 시험용 폴더를 빼지 않는다.
  - 깃 기록의 비밀번호 — 옛 검사 코드의 `password: 'qa-wrong-password'` (일부러 틀린 값). 기록 검사의 '가짜 값' 목록에 `wrong`·`fake`·`invalid`·`qa-` 가 없다.
  - `.gitignore` 에 `.env` 없음 — `.env` 를 쓰지 않는 레포에도 요구한다.

## 잘 된 점 [재현]

- 스택 6종 레포 6개에서 **실행 오류 0** — 부분 감지·경로 추출이 전부 돌았다.
- 화면 쪽(클릭·폼·장애 흉내)은 쓰기 요청을 브라우저에서 막는다 — 흔적 문제는 **서버를 직접 두드리는 영역**에만 있다.
- 화면(`index.html`)은 검사 대상이 보낸 글자를 전부 `esc()` 로 감싸 그린다.
- 회귀 테스트가 버그를 심은 레포를 끝까지 돌린다 — 위 시험 서버(`sidefx`)를 회귀 테스트 픽스처로 옮기면 P0 들이 다시 생기는 것을 막을 수 있다.

## 확인 못 한 것

- CI 템플릿을 실제 GitHub Actions 에서 돌리지 않았다 (로컬에서 같은 명령으로 흉내만).
- 7-1 에서 같은 원인(/accounts/login/ 500)이 I·E·O·B 영역에 따로따로 걸려 "먼저 고칠 것" 을 여러 칸 차지한다 — 손댈 곳 묶기가 영역을 넘어서지 않는다.
