# QA 레포 전체 점검 (2026-09-27)

`common/` 전부(러너·세션·서버 켜기·규칙 추출·자동 생성·영역 37개), `ui.js`·화면, 실행 파일, 테스트, CI 템플릿, `projects/` 를 처음부터 끝까지 읽고,
맥에서 CrossFit Grove 로 실제로 돌린 결과·로컬 DB·리포트 파일로 확인했다.
**[확인]** 은 실제로 재현·측정한 것, **[코드]** 는 코드를 읽고 판단한 것이다.

## 결론

구조와 방향은 좋다. 다만 **"검사가 대상에 흔적을 남기지 않는다"** 는 약속이 지켜지지 않고 있고, 그중 하나는 **실제 문자 발송으로 이어질 수 있다.**
새 기능보다 아래 P0 여섯 개가 먼저다.

## P0 — 실제 피해가 날 수 있는 것

### 1. 검사가 대상 DB 에 쓰레기 데이터를 남긴다 [확인]

- CrossFit 로컬 DB(`grove-pg`)의 `applications` 표가 **412행 전부 QA 가 만든 것**이었다 (QA·qa+·스크립트 문자열 흔적).
- README 는 "검사용 데이터를 만들고 끝나면 지운다" 고 하지만, 지우는 건 `seed.js` 가 만든 몇 개뿐이다.
- 지우지 않고 남기는 곳:

| 영역 | 무엇을 남기나 |
|---|---|
| F 입력 검증 (`generate.js` `fuzzRoute`) | 칸마다 10~25가지 값으로 POST — 받아 준 것은 전부 남는다 |
| R 동시성 | 같은 값으로 5번 동시에 — 중복 생성을 잡는 검사라 최대 5개가 남는다 |
| D 데이터 무결성 | 중복 검사용 두 번째 생성분 |
| M 금액 | 금액 칸 5가지 값 |
| I 주입 | 저장형 XSS 검사 — `<img src=x onerror=alert(1)>` 가 든 행이 DB 에 남는다 |
| C 권한 · W 흐름 | 지우는 경로가 없거나 응답에 id 가 없으면 남는다 |

- 고치는 방향: 영역마다 만든 것을 `ctx.created` 에 모아 `finish` 에서 한꺼번에 지운다 (지금 `seed.cleanup` 을 넓히면 된다). 지울 경로가 없으면 리포트에 "남긴 데이터 N개" 를 적는다.
- **지금 있는 412행은 손대지 않았다.** 지울지는 직접 정한다 (DB 조회 일부는 자동 모드 안전장치가 막아 행 내용까지는 못 봤다).

### 2. 자동 입력이 실제 문자를 보낼 수 있다 [코드 + 확인]

- 위험 경로 판단(`generate.js` `DANGEROUS`)이 **경로 이름만** 본다 (`sms`·`send`·`mail` …).
- CrossFit 의 `POST /api/applications` 는 이름엔 위험 단어가 없지만, 처리 코드가 **신청자 번호로 안내 문자를 보낸다** (`routes/applications.js:54` `sendSms`).
- 지금은 로컬 `.env` 에 알리고 키가 없어 발송이 안 됐다. **키를 넣는 순간 QA 한 번에 수백 통**이 `01000000000` 같은 번호로 나간다 (건당 과금, 실제 번호일 수도 있다).
- 고치는 방향: 경로가 아니라 **처리 코드**를 본다 — `sendSms|sendMail|nodemailer|aligo|twilio|solapi|stripe|toss|fetch\(https` 가 있는 쓰기 경로는 기본으로 건너뛰고 "외부로 나가는 경로라 건드리지 않음" 으로 남긴다. 번호는 누가 봐도 가짜인 값(`010-0000-0000` 대신 발송 서비스가 거절하는 형식)으로.

### 3. 폴더 경로로 돌리면 프로젝트 설정이 통째로 빠진다 [확인]

```
node run.js ~/Developer/CROSFIT-GROVE   → id CROSFIT-GROVE · 공개 경로 0개 · 계정 없음
node run.js crossfit-grove              → id crossfit-grove · 공개 경로 13개
```

- `resolveProject` 가 이름이 아니면 새 프로젝트로 만든다. 같은 폴더를 가리키는 설정이 있는지 보지 않는다.
- 결과: 일부러 열어 둔 13개 경로가 인증 결함으로 잡히고, 로그인도 못 해 영역 15개가 빠지고, 리포트가 다른 폴더(`reports/CROSFIT-GROVE`)에 쌓여 지난 검사와 비교도 안 된다.
- README 의 첫 예시와 **CI 템플릿(`docs/ci/qa-github-actions.yml`)이 바로 이 방식**이다.
- 고치는 방향: 경로로 받으면 `projectDefs()` 에서 root 가 같은 것을 먼저 찾는다 (화면의 `/api/projects/add` 는 이미 그렇게 한다).

### 4. 로그인이 설정 오류로 막히면 코드만 보는 검사까지 사라진다 [확인]

- `runner.js` `LOGIN_ONLY` 에 Q(쿼리 효율)·D(데이터 무결성)가 들어 있다.
- 둘 다 앞부분은 서버 없이 코드만 본다. 같은 CrossFit 에서:
  - 서버를 끄고 돌리면 Q 가 검사 53건·**문제 4건(N+1)** 을 잡는다.
  - 서버를 켜고 비밀번호가 틀리면 Q 가 통째로 "설정 오류로 못 잼" 이 되어 **그 4건이 리포트에서 사라진다.**
- 고치는 방향: 영역 전체를 막지 말고, 영역 안에서 로그인이 필요한 부분만 건너뛰게 한다 (`if (!ctx.sessions.owner) return { checks, partial }`).

### 5. 지난 검사와 비교할 때 "못 잰 것" 을 "고친 것" 으로 센다 [확인]

- 09:22 → 09:55 비교에서 **"새 문제 0 · 고친 것 49"** 가 나왔다. 코드는 그대로였고, 로그인이 실패해 영역들을 못 잰 것뿐이다.
- `diffWithPrevious` 가 이번에 건너뛴 영역의 옛 문제를 전부 "고쳐졌다" 로 센다.
- 고치는 방향: 두 번 다 잰 영역끼리만 새 문제·고친 것을 센다 (점수는 이미 `same` 으로 그렇게 하고 있다). 못 잰 영역은 "이번엔 못 잼 N개 영역" 으로 따로.

### 6. QA 가 보내는 요청에 제한 시간이 없다 [코드]

- `session.js` `request()` 의 `fetch` 에 `signal` 이 없다. 대상 서버가 응답을 붙잡으면 **QA 가 끝나지 않는다** (화면은 "검사 중" 에서 멈춘다).
- 11번 영역이 대상 레포에 요구하는 것(외부 호출엔 timeout)을 QA 자신이 안 지키는 셈이다.
- 같은 함수가 실패하면 한 번 더 보내는데(`go().catch(() => go())`), POST 도 다시 보내서 **R(중복 생성) 판정을 흐릴 수 있다.**
- 고치는 방향: `AbortSignal.timeout(15000)` 한 줄, 재시도는 GET 만.

## P2 — 정리하면 좋은 것

- `common/core.js` 의 `makeCtx`·`sql`(docker psql)·`walk` 은 아무도 쓰지 않는다 — 옛 도구의 흔적. `check`·`checkItems`·`kstDay` 만 남기고 지운다 (약 70줄).
- F 영역이 돌려주는 `finding`(검증 스키마 없음)을 러너가 버린다 — 화면은 `r.finding` 을 보여 주도록 짜여 있는데 값이 오지 않는다.
- `generate.js` 가 `withFormCsrf: true` 를 넘기지만 `request()` 는 읽지 않는다.
- `b_auth.js` 의 `saved = ctx.config.publicRoutes … = saved` 는 아무것도 하지 않는다.
- G 영역이 `npx tsc`·`npx eslint` 를 쓴다 — 설치가 안 돼 있으면 npx 가 인터넷에서 받으려 한다 (`tsc` 는 엉뚱한 패키지). `--no-install` 을 붙인다.
- 8번 영역의 "오류를 알렸다" 판정 단어에 `연결`·`네트워크` 가 있다 — 화면 어디에든 이 단어가 있으면 통과로 본다.
- `runner.js:93` 주석이 한 줄 아래로 밀려 있고, `project.js:99-100` 은 같은 주석이 두 번.
- **배포 주소 모드의 씨앗이 이미 있다** — `projects/crossfit-grove/check-live.js` 가 운영 사이트(cfgrove.com)를 읽기 전용으로 점검한다 (페이지, 배포 파일 대조, 지운 API, 헤더). 이걸 범용으로 옮기면 우선순위 3번(배포 주소 모드)의 절반이다.

## 잘 된 점

- 검사 결과를 O/X/△ 로 정직하게 나누고, 못 잰 영역을 점수에서 빼는 원칙이 코드 전체에 일관되다.
- 화면 쪽(클릭·폼·장애 흉내)은 쓰기 요청을 브라우저에서 막아 데이터를 건드리지 않는다 — P0-1 의 문제는 **서버를 직접 두드리는 영역**에만 있다.
- 화면(`index.html`)은 검사 대상이 보낸 글자를 전부 `esc()` 로 감싸 그린다 (대상 서버 응답이 QA 화면을 조작할 틈을 찾지 못했다).
- 회귀 테스트가 버그를 심은 시험용 레포를 끝까지 돌린다 — 오늘 고친 것들도 여기서 확인했다.
