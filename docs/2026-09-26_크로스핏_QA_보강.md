## 어떻게 찾았나

서버가 가진 API 102개 중 **어느 검사도 직접 부르지 않는 경로가 23개**였다
(문자 템플릿 5, 운동복 7, 락커 이력 3, 로그아웃 등). B 영역이 102개 전부를 "로그인 없이" 두드리긴 하지만,
기능이 맞게 도는지는 아무도 안 봤다.

## 결정과 근거

- **로그인 잠금은 가짜 IP로 시험한다.** 잠금이 IP별이라 진짜 IP를 잠그면 뒤 검사가 다 막힌다.
  `X-Forwarded-For` 로 가짜 IP만 잠근다. 서버의 `trust proxy` 설정 덕에 로컬에서만 통하는 방법이다.
  기존에는 "코드에 `MAX_LOGIN_ATTEMPTS` 가 있다"는 정적 확인뿐이었다.
- **E 에서 400 도 통과로 센다.** 값부터 검사해서 거절하는 건 거짓말이 아니다. 문제는 200 "완료" 뿐이다.
- **접근성에서 확인 필요로 빼 둔 것** — placeholder 만 있는 입력칸, 앞에 `<label>` 은 있는데 `for` 로 연결 안 된 입력칸.
  눈으로는 이름이 보이니 결함이라 단정하지 않는다. 처음엔 이것까지 불합격으로 세서 109건이 나왔는데,
  대부분이 이 경우라 확인 필요로 옮겼다(→ 불합격 16건).
- **문자 발송(`/api/sms/send`)은 시험하지 않는다.** 실제 문자가 나가고 돈이 든다.
- **운동복**은 서비스가 끝났지만 경로와 화면이 살아 있으므로 시험한다. 검사가 만든 이력은 검사가 지운다.

## 확인 방법

사용자가 3000번에서 데모 DB로 서버를 돌리고 있어서 건드리지 않았다.
**버리는 Postgres(55433) + 서버(3100)** 를 따로 띄워 돌리고 끝나고 지웠다.
검사 데이터 잔여 0건, 진짜 IP가 잠기지 않은 것(뒤에 도는 H 의 로그인 통과)까지 확인했다.
빈 DB 에서 잰 리포트라 `reports/` 에는 남기지 않았다.
